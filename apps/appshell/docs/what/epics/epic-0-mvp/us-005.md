# User Story 005: Design tokens and tailwind.config.ts

## As a...
Product Owner

## I want...
Des design tokens définis en CSS variables et Tailwind

## So that...
Tous les écrans utilisent les mêmes couleurs/espacements/typographie

---

## Description

Établir un système centralisé de design tokens qui:
1. **CSS Custom Properties** — définit les variables light/dark dans `globals.css`
2. **Tailwind Config** — consomme ces variables pour colors, spacing, typography
3. **Consistency** — tous les composants et écrans utilisent ces tokens (jamais de valeurs hardcodées)

Les tokens doivent couvrir:
- **Couleurs** — background, foreground, accent, border, muted-background, muted-foreground
- **Espacements** — scales: sm, md, lg, xl
- **Typographie** — font sizes, weights, line heights

---

## Acceptance Criteria

```gherkin
Given je suis développeur créant les tokens
When j'implémente globals.css et tailwind.config.ts
Then globals.css doit:
  - Définir un bloc :root avec variables light mode
  - Définir un bloc .dark avec variables dark mode
  - Inclure au minimum:
    * --background: color
    * --foreground: color
    * --accent: color
    * --border: color
    * --muted-background: color
    * --muted-foreground: color
  - Utiliser rgb() ou hsl() pour faciliter la variation de couleur
  - Inclure Tailwind directives (@tailwind base, components, utilities)

And tailwind.config.ts doit:
  - Importer les variables CSS comme couleurs:
    ```
    colors: {
      background: 'hsl(var(--background))',
      foreground: 'hsl(var(--foreground))',
      accent: 'hsl(var(--accent))',
      border: 'hsl(var(--border))',
      'muted-background': 'hsl(var(--muted-background))',
      'muted-foreground': 'hsl(var(--muted-foreground))',
    }
    ```
  - Définir une scale d'espacement (sm, md, lg, xl)
  - Définir une scale de typographie (font sizes, weights)
  - Inclure dark mode support (class strategy)

And tous les composants doivent:
  - Utiliser les classes Tailwind (bg-background, text-foreground, etc.)
  - Ne jamais hardcoder de couleurs (pas de bg-blue-500)
  - Ne jamais utiliser des valeurs pixel brutes (utiliser Tailwind spacing)
  - Ne jamais utiliser des fonts non-déclarées (utiliser Tailwind typography)

And la documentation doit:
  - Expliquer les tokens disponibles
  - Montrer comment les utiliser dans les composants
  - Décrire la stratégie light/dark mode
```

---

## Definition of Done

- ✅ `src/styles/globals.css` existe avec :root et .dark
- ✅ Au minimum 6 CSS custom properties définies (colors)
- ✅ Variables CSS utilisent rgb() ou hsl() pour flexibilité
- ✅ `tailwind.config.ts` consomme les variables CSS
- ✅ Colors, spacing, et typography sont configurés
- ✅ Dark mode utilise la stratégie "class" (classe .dark)
- ✅ Aucun composant n'utilise de couleurs hardcodées
- ✅ Aucun composant n'utilise de valeurs pixel brutes
- ✅ Test: changer une variable CSS change l'apparence de tous les composants
- ✅ Test light/dark mode: couleurs switchent correctement
- ✅ TypeScript types sont corrects pour tailwind.config.ts
- ✅ `npm run build` succeeds sans warnings
