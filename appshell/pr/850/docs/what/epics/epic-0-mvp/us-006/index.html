User Story 006: MSW + React Query pattern

As a…

Section titled “As a…”

Developer

I want…

Section titled “I want…”

Un pattern MSW → React Query fonctionnel (dev-only)

So that…

Section titled “So that…”

Je peux fetcher et cacher les données sans dépendre d’une API réelle

Description

Section titled “Description”

Implémenter la couche de récupération de données avec:

  1. MSW (Mock Service Worker) — mock les API responses en développement seulement
  2. React Query — gère le fetch, caching, et synchronisation des données
  3. useUsers() hook — démontre le pattern avec un exemple concret
  4. HomeScreen — affiche la liste des users dans des Cards

Le pattern doit être:

  • Dev-only — MSW actif seulement quand import.meta.env.DEV
  • Production-safe — zéro overhead en prod (code tree-shaken)
  • Type-safe — TypeScript partout

Acceptance Criteria

Section titled “Acceptance Criteria”

Definition of Done

Section titled “Definition of Done”
  • ✅ MSW est installé via npm
  • ✅ mocks/browser.ts initialise le worker
  • ✅ mocks/handlers.ts définit GET /api/users
  • ✅ mocks/data/users.ts fournit les données mock
  • ✅ main.tsx initialise MSW avec import.meta.env.DEV guard
  • ✅ lib/query-client.ts exporte un QueryClient singleton
  • ✅ main.tsx wraps l’app dans QueryClientProvider
  • ✅ hooks/useUsers.ts existe et utilise useQuery
  • ✅ HomeScreen.tsx utilise useUsers() et affiche les Cards
  • ✅ Test dev: npm run dev → HomeScreen affiche users mock
  • ✅ Test prod: npm run build && npm run preview → pas d’erreurs MSW
  • ✅ Pas de console errors/warnings
  • ✅ React Query DevTools fonctionnent (optional mais préférable)
  • ✅ Tous les fichiers ont types TypeScript complets
